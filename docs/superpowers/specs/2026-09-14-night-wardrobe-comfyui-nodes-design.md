# 夜之主衣柜 ComfyUI 节点闭环设计

## 目标

提供一个本地 ComfyUI 自定义节点包，让衣柜里的角色、服装、画师、场景、LoRA 和生图记录能直接参与节点工作流。首版只覆盖本地 SQLite 与 ComfyUI 原生能力，不联网、不上传数据、不修改既有图片文件。

## 节点包与安装

节点源代码放在仓库 `comfyui_nodes/night_wardrobe/`。将该目录复制或链接到 ComfyUI 的 `custom_nodes/night_wardrobe/` 后即可载入。节点包默认读取同一衣柜仓库下的 `tag_manager/tag_wardrobe.sqlite3`；无法定位时要求用户在节点的“衣柜数据库路径”输入框中指定绝对路径，并显示明确错误。

节点每次刷新选项时只读取 SQLite，不调用夜之主衣柜 HTTP 服务，因此 ComfyUI 和衣柜网页可以独立启动。数据库连接只读用于组合与 LoRA 选择；仅“保存并记录图源”节点拥有写入记录的权限。

## 节点一：衣柜提示词组装

**名称：** `夜之主衣柜 · 提示词组装`

输入：衣柜数据库路径、角色、服装套组、画师串、场景、负面模板、自定义正面、自定义负面。角色、画师串、场景、负面模板的候选项来自既有衣柜表，未选择的项不参与输出。

输出：`正面提示词`、`负面提示词`、`LoRA 配置`。`LoRA 配置`为节点间使用的 `NIGHT_WARDROBE_LORAS` 数据，不把 JSON 暴露给用户作为复制目标；它包含 LoRA 文件名、模型权重与 CLIP 权重。文本拼接遵守工作台已有顺序：角色 LoRA → 角色外观 → 服装 → 画师串 → 场景 → 自定义。

## 节点二：衣柜 LoRA 载入

**名称：** `夜之主衣柜 · LoRA 载入`

输入：`MODEL`、`CLIP`、节点一输出的 `NIGHT_WARDROBE_LORAS`，以及可选的“模型目录覆盖”。

输出：更新后的 `MODEL`、`CLIP`。

节点通过 ComfyUI 原有的 LoRA 加载函数与模型路径体系加载 LoRA，按配置顺序逐个叠加；缺文件、无效权重或加载失败立即中止并报告具体 LoRA 名称，不静默跳过。空 LoRA 配置原样返回模型与 CLIP，确保普通提示词工作流可用。

## 节点三：保存并记录图源

**名称：** `夜之主衣柜 · 保存并记录图源`

这是输出节点。输入：`IMAGE`、正面提示词、负面提示词、`NIGHT_WARDROBE_LORAS`、Checkpoint 名称、文件名前缀与可选工作流提示对象。输出：UI 中的已保存图片。

节点以 ComfyUI 的输出目录和安全文件名前缀保存 PNG，并写入 ComfyUI 标准 `prompt` / `workflow` 元数据。图片保存成功后，才把相同图源信息写入衣柜现有输出记录；数据库记录失败不会删除图片，而是在节点结果中显示“图片已保存、图源记录失败”。不扫描历史目录，不覆盖已有输出，不更改任何既有图片。

## 数据流

`衣柜提示词组装` 的正面/负面文本分别连接文本编码节点；`LoRA 配置` 连接 `衣柜 LoRA 载入`；更新后的模型、CLIP 继续进入采样链；采样器解码后的图片和同一套文本/LoRA 配置进入 `保存并记录图源`。这样每张由该链路产生的图都可以在衣柜“生图查看”中追溯角色、LoRA、提示词和工作流。

## 错误处理与兼容性

- 数据库不存在、表缺失或查询失败：节点给出数据库路径与可执行修复提示，不创建空数据库。
- 空资源选择：提示词节点仍输出自定义文本；LoRA 节点原样透传 `MODEL` 与 `CLIP`。
- 同一 LoRA 多次出现：提示词节点按名称合并，保留用户最后指定的权重。
- 节点名称、端口类型与工作流字段首版即固定；后续只增加可选输入，避免破坏已保存工作流。
- 所有行为本地执行；不增加网络请求、遥测或后台扫描。

## 测试

- 数据访问：角色、服装、配方、场景、负面模板读取与缺库错误。
- 提示词：拼接顺序、空选择、自定义补充、LoRA 去重。
- LoRA：空配置透传、顺序叠加、缺文件报错（使用 ComfyUI 加载接口替身）。
- 保存记录：PNG 元数据、成功写库、写库失败仍保留图片、绝不覆盖原有文件。
- 注册：三个节点能被 ComfyUI 的 `NODE_CLASS_MAPPINGS` / `NODE_DISPLAY_NAME_MAPPINGS` 发现。
