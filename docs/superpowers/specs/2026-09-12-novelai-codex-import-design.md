# NovelAI 法典完整导入设计

## 目标

把三份所长 NovelAI 法典完整保存到夜之主衣柜，同时让单个 Tag 的中文释义、完整 Prompt 配方和明确的角色资料各自保存在正确的数据结构中。

## 当前状态

- `tags` 已有 20,000 条临时导入记录；英文 Tag 可检索，但所有 `zh` 字段被错误填入首次出现的 Prompt 标题。
- 三份 DOCX 是中文条目标题与英文 Prompt 段落的合集，并不是单一 Tag/中文翻译对照表。
- 本机 tagcomplete 扩展提供离线 `danbooru.zh_CN_SFW.csv`，包含可信的英文 Tag 到中文释义映射。
- 现有 `recipes` 表可保存完整 Prompt，但页面只支持四种类型且查询固定限制为 200 条；无法作为大规模文档归档直接使用。

## 方案

### 1. Tag 词典

以离线 `danbooru.zh_CN_SFW.csv` 为唯一自动中文来源。对当前及后续解析出的英文 Tag：

- 有精确词典命中时，写入对应中文释义。
- 没有命中时，`zh` 保持空字符串，不根据法典标题猜测翻译。
- 保留现有分类器产生的分类和二级分类，但把 DOCX 条目标题移至 `notes`，仅作溯源信息。

### 2. Prompt 档案

每个法典中的有效“中文标题 + 英文 Prompt”条目创建一条配方记录。原始 Prompt 不拆分、不清洗、不重排；标题、文档名和目录层级写入单独字段或可检索备注。

为支持大量归档记录，新增 `codex_prompt` 配方类型，并为 `/recipes` 增加基于 `offset`/`limit` 的分页与目录/来源筛选。默认列表不加载全部记录。

### 3. 角色卡

只处理有明确角色名和可分辨外观、触发词或服装块的 OC 条目。角色名写入 `characters.name`，外观 Prompt 写入 `appearance`，服装块写入 `character_outfits`。无法可靠分辨结构的内容仍保留为 Prompt 档案，不创建猜测性的角色卡。

### 4. 导入运行与可恢复性

导入器使用单独的本地脚本，不修改原 DOCX。它输出：

- 完整 Prompt 档案 JSON；
- Tag 校正和导入报告；
- 角色卡候选报告。

执行前创建 SQLite 备份；导入按来源和稳定导入标识幂等更新。出现无法解析的段落时，记录到报告，不阻断其余导入。

## 数据流

DOCX 段落 → 条目识别与目录上下文 → 完整 Prompt 档案

同一英文 Prompt → 仅用于抽取独立 Tag → 离线中文词典精确匹配 → Tag 库

明确 OC 结构 → 角色卡与服装套组

## 验收标准

- 已有 Tag 的错误 `zh` 全部清空或被离线词典的精确映射替换。
- 每个识别出的法典 Prompt 都可按标题、来源和目录层级搜索并复制完整原文。
- 配方页可分页浏览，不因大量记录导致一次渲染全部卡片。
- 角色卡只含具有明确结构的 OC，无法确定的条目保留在 Prompt 档案中。
- 导入前数据库可恢复，重复运行不会生成重复记录。
